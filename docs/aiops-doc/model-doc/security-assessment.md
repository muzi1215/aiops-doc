# 平台安全成熟度评估报告（Security Assessment）

> **定位**：以企业生产安全标准（参考等保 2.0 / OWASP ASVS / 企业安全基线）对平台自身安全进行逐项评估，输出评级、差距清单与整改路线图。安全时以此为准——**诚实评估比自吹自擂更能体现安全工程素养**。
>
> **评估日期**：2026-08-08 | **版本**：v2.0（安全加固后复评）| **评估对象**：平台自身（后端 + 前端 + 部署）| **评估人**：lx
>
> **v2.0 变更**：完成 P0 高危整改（凭证最小权限），评分 59 → **62**，凭证管理维度 6 → 8，运维安全 4 → 5

---

## 一、评估方法与评级模型

### 1.1 评级等级

| 等级 | 定义 | 含义 |
|---|---|---|
| L5 合规认证 | 通过等保/ISO27001 等第三方测评 | 可对外提供服务/过审 |
| L4 企业增强 | 企业基线之上 + 纵深防御完善（KMS/双因子/WAF/监控告警） | 生产环境推荐 |
| **L3 企业基线** | 满足企业生产应用的安全底线（认证/授权/加密/审计/防注入） | 可上线内部使用 |
| L2 基础防护 | 有基础认证与常见漏洞防护，但体系不完整 | 开发/测试环境 |
| L1 初阶 | 基本无防护 | 不可暴露 |

### 1.2 评估维度（10 项）

身份认证 / 访问控制 / 数据保护 / 凭证管理 / 安全审计 / 应用安全 / 网络安全 / 运维安全 / 备份与容灾安全 / 合规与流程

## 二、总体评级结论（v2.0 复评）

```
┌──────────────────────────────────────────────────────────┐
│  总体评级：L3 企业基线（达成 62/100 分，较 v1.0 +3）         │
│                                                          │
│  ★ 应用层安全扎实：认证/权限/防注入/审计达到企业基线          │
│  ✅ P0 高危项已整改：通用 root 凭证 → 只读账号 + sudoers     │
│      命令白名单 + MySQL 最小权限（爆炸半径大幅缩小）          │
│  ▲ 剩余缺口：HTTPS/密钥 KMS/监控告警/漏洞管理（P0-P1 项）    │
│  ✗ 合规流程未启动：等保测评/隐私政策/漏洞管理                │
└──────────────────────────────────────────────────────────┘
```

**一句话结论**：平台**应用层安全达到企业基线**（L3），**最高危的凭证风险（v1.0 P0 第 1 项）已整改完成**——被管服务器从"root 全权限"降为"只读命令白名单"，即使凭证泄露也无法破坏服务器。剩余差距集中在部署与运营层（HTTPS、密钥管理、监控告警、漏洞管理），是**可补齐的工程投入**，不是架构缺陷。

### v2.0 安全加固实录（2026-08-08）

| 整改项 | 具体措施 | 状态 |
|---|---|---|
| 凭证最小权限（P0） | `scripts/create_patrol_account.sh` 一键创建只读巡检账号：20 位随机密码 + sudoers 命令白名单（top/free/df/ss/ps/systemctl 查询等全部只读）+ docker 组 + 自检 | ✅ 已上线 |
| MySQL 监控账号最小权限 | 同名账号 + auth_socket 免密 + `PROCESS, REPLICATION CLIENT`（纯只读，无数据读写）| ✅ 已上线 |
| 命令白名单文档化 | `docs/ssh-command-whitelist.md`：全部 SSH 命令清单 + 授权边界 + 后续扩展接入规范 | ✅ 已上线 |
| 实测验证 | 平台凭证切换 aiops_patrol 后全链路巡检/采集/告警/工单/通知正常；MySQL P99 深度指标恢复；危险命令（rm -rf/systemctl stop/DROP TABLE）全部被拒 | ✅ 已验证 |

**安全效果**：凭证泄露的后果从"服务器沦陷（任意命令）"降为"只能执行白名单只读查询"——爆炸半径从【服务器全权限】缩小到【只读窥探系统状态】。

## 三、十维度评分明细

| 维度 | v1.0 | **v2.0** | 评级 | 现状（真实实现） | 主要差距 |
|---|---|---|---|---|---|
| 1. 身份认证 | 9 | **9** | L4 | JWT(HS512)+Redis Session 双因子；bcrypt 密码（旧 MD5 自动升级）；递增降级锁定（5次→5分钟→15分钟→30分钟→1天）；封禁/停用/到期自动解封；多端控制 | 无 MFA（双因素）；token 存 Cookie（XSS 风险） |
| 2. 访问控制 | 9 | **9** | L4 | RBAC 三表关联（user_role→role_menu→menu）；**超管也走角色无硬编码放行**；按钮级权限；新增接口未登记菜单即 403；数据级校验（工单处理人匹配） | 无细粒度字段级权限；部门数据隔离（row-level）未覆盖全部接口 |
| 3. 数据保护 | 5 | **5** | L2→L3 | 凭证 Fernet 加密存储；密码 bcrypt；传输走 SSH 加密通道 | **数据库明文存储业务数据**（无 TDE/字段级加密）；备份文件明文；无数据脱敏 |
| 4. 凭证管理 | 6 | **8** | L3→L4 | ✅ 加密存储 + 按需解密；✅ **专用只读巡检账号**（sudoers 命令白名单，全只读）；✅ MySQL 同名只读账号（PROCESS/REPLICATION CLIENT 最小权限）；✅ 20 位随机密码；命令白名单/黑名单 + 120s 超时 + 执行审计 | FERNET_KEY 仍在 .env（未上 KMS）；无自动凭证轮换；交互式 SSH 仍为黑名单模式 |
| 5. 安全审计 | 7 | **7** | L3 | 登录日志（IP/OS/浏览器/成败/耗时）；操作日志（@Log AOP：URL/IP/地理位置/用户名/参数/结果，成败都记）；SSH 交互执行审计；在线用户可踢 | 日志无敏感操作专项告警联动；无日志集中收集（SIEM）；审计日志无防篡改 |
| 6. 应用安全 | 7 | **7** | L3 | **全 SQLAlchemy 参数化（零字符串拼接 SQL）**；Vue 模板转义防 XSS；富文本白名单；文件上传类型校验；危险命令拦截 | CSRF 防护依赖 token 机制（Cookie 场景弱）；无上传内容扫描；无依赖漏洞扫描（pip audit/npm audit 未接入 CI） |
| 7. 网络安全 | 4 | **4** | L2 | 登录限速（递增锁定）；SSH/HTTPS 加密通道 | **未强制 HTTPS（生产默认 HTTP 部署）**；无 WAF；无 IP 白名单/防火墙策略文档；API 无全局速率限制 |
| 8. 运维安全 | 4 | **5** | L2→L3 | 日志 30 天滚动压缩；Docker 多阶段构建；✅ 账号管理脚本化（一键创建 + 自检 + 文档化） | 无漏洞扫描/补丁流程；无平台自身监控告警（磁盘/CPU/异常登录）；无变更审批流程 |
| 9. 备份与容灾 | 6 | **7** | L3 | 数据库自动备份 + OSS/COS 双云 + 跨云复制 + 完整性校验 + 过期清理；备份失败自动通知；✅ **备份账号最小权限已落地**（SELECT/LOCK TABLES/RELOAD/SHOW VIEW/TRIGGER，纯只读，实测 SHOW GRANTS 验证） | 备份文件明文；无恢复演练 SOP；云桶权限无定期审计 |
| 10. 合规与流程 | 2 | **2** | L1 | 操作/登录日志留存 30 天（部分满足留存要求） | 无等保测评；无隐私政策/数据保护声明；无安全事件响应预案；无渗透测试记录 |

## 五、安全评估

```
① 结论先行：平台应用层安全达到企业基线（L3，62/100），认证/权限/防注入/审计是强项；
   最高危的凭证风险已整改（只读账号 + 白名单），剩余差距在部署与运营层。

② 强项举证（讲实现细节）：
   - 认证：JWT + Redis Session 双因子，踢下线/封禁即时生效；递增降级锁定防爆破
   - 权限：RBAC 三表关联，超管也走角色——无硬编码放行，防权限绕过
   - 防注入：全 SQLAlchemy 参数化，零字符串拼接 SQL
   - 凭证（整改后）：专用只读账号 + sudoers 命令白名单（全只读）+ MySQL 最小权限账号
     ——凭证泄露也只能执行只读查询，无法破坏服务器（爆炸半径从"全权限"降到"只读窥探"）

③ 诚实短板（主动讲，最加分）：
   - 已整改：root → 只读账号（脚本一键创建 + 实测验证危险命令全被拒）
   - 待整改：FERNET_KEY 在 .env → 上 KMS；生产未强制 HTTPS → Nginx TLS + HSTS；
     备份明文 → 加密；无自动凭证轮换

④ 改进路线：P0（HTTPS/KMS/凭证轮换）/ P1（备份加密/监控告警/漏洞扫描）/ P2（等保合规）
   分级推进，每项都有明确方案与投入评估——证明有完整的"发现问题 → 整改 → 复评"治理闭环。
```
